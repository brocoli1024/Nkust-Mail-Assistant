# 2026-11-02 公開公告閱讀流程改良（第1～3項）

## 設計與修改範圍

依使用者同意的局部設計，保留既有FastAPI/Jinja、公開資料表、IndexedDB修正及待辦，不新增服務、資料庫schema或權限。

- 清單傳遞q/category/audience/page至詳情；頂端與底部返回只組合本站公開清單路徑，返回連結帶原公告row anchor。每分頁sessionStorage額外保存公開清單路徑、公告ID、捲動距離與時間，30分鐘內恢復；預設query正規化比對。儲存不可用、過期或另開分頁時使用row anchor，不讀私人路徑、Gmail或修正。
- 「修正我的資訊」改為「補充或修正這則公告」，說明只改自己的整理結果，不改官方公告或帳號資料；各欄位分別展開。既有欄位名稱、修正patch、歷史、CSRF及帳號隔離沿用。讀取修正失敗時顯示次要重試入口並禁用保存；首次重試成功必須回填既有修正，不能把空白inherit表單當現況。
- 公開詳情主要操作放在行動卡頂端，使用同一個既有待辦controller。加入成功顯示「查看我的待辦」；未保存修正禁用加入。讀取失敗與版本衝突自動展開原因及重試。依已保存且通過URL驗證的form/tickets提供各自來源連結，沒有資料時不猜報名網址。連結不代表資格或仍開放報名。
- 手機縮小公告標題、精簡導覽換行；主要操作在長行動卡內sticky，視窗高度<=600px改為一般排版，避免短螢幕或鍵盤占用時過度遮擋。

## 限制與回復

sessionStorage僅同一分頁的短期閱讀位置；頁面內容或尺寸改變可能影響精確像素位置，row anchor作為後備。私人Gmail的正式登入流程未重新授權或執行；其表單後端保存與帳號隔離測試仍在完整驗收中。這次不改第4～5項資訊層級及清單功能。

應用程式可回復至5d99cc2，沿用schema0009與既有Linked form讀取相容性；不需要刪除使用者修正或待辦。新sessionStorage key不影響IndexedDB資料。

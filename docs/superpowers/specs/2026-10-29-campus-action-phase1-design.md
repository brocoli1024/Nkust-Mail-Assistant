# 校園通知待辦助手：第一階段設計

日期：2026-10-29（Asia/Taipei）

狀態：使用者於 2026-10-29 明確回覆「同意書面規格」。下一步為實作計畫審閱與執行方式選擇；不代表已實作或已部署。

## 1. 目的與完成標準

服務一般高科大學生，先讓訪客免登入找到公告，再為「看懂行動與期限 → 自行加入待辦 → 追蹤完成」建立入口。第一階段僅完成公開閱讀與合成示範，不提前實作行動卡或待辦。

訪客從首頁即可進入公開公告，搜尋標題與摘要、選擇分類、開啟詳情與官方來源。沒有 Gmail 或 AI 金鑰，也能進入明確標示的合成示範。Gmail 是選用整合，不是公開閱讀的前置步驟。

公開首頁、清單、詳情均能看到來源、最後成功更新時間與收錄限制；來源維護失敗時顯示提示並保留已收錄資料。手機操作、鍵盤操作、空白狀態及錯誤提示均納入驗收。

## 2. 現況與證據界線

- 基準為工作區 `codex/web-deployment` 的 4271ad4。`main` 主要為單人本機版；多人正式入口是 `app.web:app`，不可將 `app.main:app` 公開掛載。
- 已有公開清單、搜尋、分類、分頁、學生相關篩選、公開獨立資料表、來源狀態及失敗保留測試。第一階段沿用，不重寫同步服務。
- README、維護手冊仍有「尚未發布」文字；未提交的 2026-10-28 發布紀錄記載公開版曾上線及當時 121 則資料。這屬歷史紀錄，尚未於本次確認今天正式環境的版本、數量或可用性。
- 公開來源僅為指定最新消息 RSS／歷史清單可取得的內容，摘要可能截短；不能宣稱全校、全歷史、每日更新或即時更新。
- 本次無法透過網頁讀取工具檢視參考站；功能比較依使用者提供的說明，不聲稱已完成現場比較。

## 3. 選定方案與取捨

沿用 FastAPI、Jinja、既有 CSS 與公開資料模型，加入獨立合成資料提供者與示範路由。此方案保持依賴與部署方式，便於以既有帳號隔離測試驗收。

不選擇只修改單人 Dashboard：無法改善多人網站主要入口。不選擇新建前端或新服務：會增加部署與資料隔離成本，對第一階段沒有必要。

「免 Gmail／AI 金鑰」指學生端體驗及示範請求不使用這些整合。既有多人服務啟動仍要求管理者 OAuth、Session 與資料庫設定；第一階段不改寫整個啟動架構，也不宣稱整套多人網站可零設定啟動。

## 4. 頁面與資料流

### 4.1 正式公開頁

- `/`：主要入口為「瀏覽公開公告」及「體驗合成示範」；Gmail 標為「選用：我的 Gmail 公告」，提示仍有 Google 測試名單限制。
- `/public/announcements`：保留 GET 搜尋、分類、對象及分頁，篩選變更重設頁碼，搜尋保留分類。無 JavaScript 時仍可提交表單。
- `/public/announcements/{id}`：顯示來源摘要與官方連結；補上與清單一致的來源狀態。無摘要時明示來源未提供，無合法連結時不輸出可點擊的危險 URL。
- 來源狀態區共用模板，避免三頁文案漂移。來源名稱、上次成功時間、收錄範圍及更新失敗提示不必展開才看得到；較詳細的歷史掃描資訊可折疊。
- 時間使用既有 Asia/Taipei 顯示方式。無紀錄顯示「尚無成功更新紀錄」，不以頁面讀取時間或最近失敗時間替代成功時間。

正常公開請求只讀公開表，不解析登入 Session、不讀私人郵件、不發出來源、Gmail 或 AI 請求。

### 4.2 合成示範

- `/demo` 提供獨立清單，支援同樣的搜尋與分類操作；`/demo/announcements/{demo_id}` 提供示範詳情。使用固定字串 ID，與正式公開公告 ID 分開。
- 固定三則合成資料涵蓋獎學金、活動及行政通知，至少一則缺少摘要或日期，展示未知狀態。日期固定、不隨今天移動，不宣稱目前仍可報名。
- 每個示範頁有醒目文字：「合成示範資料，非高科大真實公告，請勿據此報名或申請」。日期標為示範日期；無來源更新時間或真實收錄數。
- 不捏造真實單位發布或有效報名連結；需要外部導覽時只能明確連到學校最新消息入口，不能標成這則合成公告的官方原文。
- 使用不可變或請求內複製的資料；不將合成資料寫入資料庫，不呼叫 AI、Gmail、來源擷取，不保存使用者行為。示範請求不依賴資料庫查詢，但仍依附既有服務啟動。
- 第一階段僅示範閱讀與篩選，不顯示尚未實作的待辦按鈕或完成通知。

### 4.3 空白、載入與錯誤

- 區分「目前尚無收錄資料」與「沒有符合篩選的公告」。前者提供示範入口，後者提供清除篩選。
- 表單導航時以可存取的狀態訊息顯示「正在搜尋／更新清單」，返回上一頁時恢復可用狀態；無 JavaScript 仍可閱讀與操作。
- 來源更新失敗表示維護結果，公開頁仍回傳既有資料，不將失敗誤報成零則。
- 公開／示範頁的參數錯誤與服務讀取失敗提供繁中提示及安全的返回、重試連結；維持 4xx／503 等真實狀態碼，不改成成功頁。
- 錯誤處理限於本次頁面；保留既有私人與 API 錯誤契約，不輸出 SQL、連線資訊或第三方例外。
- 320px 及 390px 寬度不得水平溢出；長標題可換行，輸入與主要操作可觸控，焦點清楚。沿用現有色彩，不新增主題。

## 6. 隔離與正式環境界線

公開、合成示範與私人 Gmail 三種資料不得共用查詢回退。即使收到有效或偽造 Cookie，公開及示範路由也不讀取私人帳號；登入不能令示範頁混入私人內容。

保留 Jinja 自動跳脫、來源 URL 驗證、既有 CSP 及 no-store。PWA 不新增公告、私人內容或示範資料離線快取。

不推送部署分支、不觸發正式部署、不執行正式 migration、不讀寫正式資料庫、不修改 OAuth、不啟用付費或排程服務。測試資料庫必須使用獨立臨時位置；不得繼承正式連線作為測試目標。

既有未提交的單人 Dashboard CSS／JS／index、字型及 readiness 文件不屬本次交付，不覆寫、不重設、不混入提交。

3. 示範頁不呼叫資料庫查詢、Session、Gmail、AI 或擷取；所有頁標示合成，未知 ID 回 404，HTML 安全跳脫，無新增資料庫資料。
4. 公開與示範路由不外洩私人標記；私人路由仍要求登入，雙帳號隔離測試通過。JavaScript 篩選／載入狀態驗證與手機、鍵盤檢視完成。

## 8. 後續階段銜接（本次不實作）

第二階段以公開標題／摘要、私人原文及既有 `date_evidence`、分析結果作為帶來源的輸入。截止與活動日期獨立；缺少年份、衝突、資格或材料不足時標「待確認」。來源摘要不冒充全文，AI 不是唯一證據。修正值與原解析分開，保留原文依據及來源版本。

第三階段候選方案是公開待辦保存在匿名裝置、私人待辦依帳號保存在既有資料庫；採用前仍須於該階段具體說明遺失、共用裝置與跨裝置取捨。合成資料使用獨立命名空間，不混入正式待辦。系統可行動提示不自動加入待辦；稍後時間到達後在下次開啟或重新整理時重新出現。

第四階段僅匯出使用者確認的活動或截止，已知日期無時間用全天，不確定日期拒絕直接匯出，使用 Asia/Taipei 並附來源；只能宣稱下載檔案。

第五階段以官方 URL／可靠識別碼建立關聯，不以相似標題合併；保留來源原文及版本，私人原文不進入公開資料。現有公開資料覆寫更新不是完整版本歷史，不宣稱已具備此能力。

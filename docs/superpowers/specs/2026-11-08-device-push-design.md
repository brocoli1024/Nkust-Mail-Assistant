# 截止前裝置推播與加入主畫面引導

日期：2026-11-08。狀態：使用者已於2026-11-08同意書面規格，尚未實作／啟用。

## 已確認的需求與順序

使用者要求先建置公告待辦的截止前裝置推播，再補加入主畫面引導；必須包含iPhone，保留一般學生免登入、不提供Gmail整合入口。使用者已選擇增加Cloudflare免費定時觸發，沿用Render及Neon，不啟用付費方案。本設計不代表正式推播已可使用。

先完成後端與裝置推播、本機及替身驗收；再接上學生可見的安裝引導；兩者完成後才正式啟用iPhone流程。不能先對iPhone宣稱推播可用而缺少必要操作引導。

## 現況與必要銜接

正式程式afa0f03（文件後續b11092f），schema0010，Render免費Web服務與Neon；GitHub負責原公告維護。公開待辦由todo-store.js保存至IndexedDB，不發網路；todos.js處理完成、稍後與移除。既有PWA manifest、圖示、service worker已部署，但沒有推播訂閱、發送或到期排程。

公務公告目前只有摘要與原文，沒有加入待辦入口；公開最新消息則已有行動卡／裝置待辦。為讓公務公告也能使用本功能，新增簡易「加入待辦／確認截止」區，沿用裝置保存格式與可靠官方來源識別，不恢復公務公告行動資訊卡、不重做摘要。

## 學生操作

1. 加入待辦仍只保存在此瀏覽器，預設不開啟通知、不上傳完整待辦快照。
2. 在待辦自行按「開啟截止提醒」，閱讀最少資料保存說明，確認日期及提醒時間，再依瀏覽器提示允許通知。拒絕／不支援／未加入iPhone主畫面時，待辦仍可使用，不反覆彈窗。
3. 免Google登入、免Email。每個瀏覽器／主畫面App是獨立裝置，不自動共用提醒或私人資料。Safari分頁與主畫面App的儲存不能假定相同；以實機驗證，必要時提示從主畫面重新加入，不能偷偷上傳搬移。
4. 提供提醒狀態、送測試通知、取消單筆提醒、關閉此裝置全部提醒。完成／移除待辦會排入提醒取消；修改期限須重新確認，不能沿用未確認的新日期。
5. 未連線的本機操作照常保存，但顯示「提醒變更待連線同步」，直到伺服器確認才宣稱已更新／取消。稍後處理只延後站內重新出現，不變動已明確設定的截止提醒；介面清楚說明兩者不同。

## 日期與正確性

- 所有畫面採Asia/Taipei；伺服器保存UTC。只提醒使用者已核對確認的截止日期／時間，不把AI結果直接當成排程依據。報名截止與活動日期分開，提醒只取截止。
- 有明確截止時間時，預設提前24小時，使用者可改提醒時間，但必須在未來且早於確認的截止。若日期明確、官方未提供時間，預設「截止日期前一天09:00」，不捏造23:59截止；日期型提醒最晚於截止日期開始前失效。
- 預設提醒時間已過時不自動補發舊通知；要求另選合規時間。未知／推定年份／過期／待確認日期不得直接啟用。官方日期缺失時可由使用者明確填入並確認自己的提醒依據，不宣稱為官方已載明。
- 保留本機原始解析與依據、來源快照。伺服器只保存必要日期與公開來源版本識別，不保存修正全文。來源版本已變更時不自動猜新期限，標為需重新核對；到原提醒時間可送一次「公告已更新，請核對截止」提示，不聲稱舊截止仍正確。
- 每筆使用固定通知識別與revision；取消／變更成功後不得由舊請求覆寫。伺服器不發送已取消、完成、過期或舊版本工作。已提交推播服務的訊息不能保證撤回；離線完成也不能假稱已取消伺服器提醒。

## 架構選擇與取捨

選擇：既有FastAPI負責匿名裝置、提醒API及Web Push發送；Neon持久保存；Cloudflare Worker只執行每5分鐘固定HTTPS觸發。不新增第二個公告資料庫，不將Gmail或私人DB憑證給Cloudflare。原GitHub公告維護保持獨立，不作為提醒的主要排程。

對比：只用GitHub最少服務，但已觀察數小時延遲，官方亦說明schedule可能延後／丟棄；付費常駐排程不在本次範圍。免費Cloudflare是使用者已選方案。每5分鐘觸發是檢查頻率，不是裝置準時送達保證；Render冷啟動、免費時數、排程或推播服務及裝置離線均可能延遲。Render每工作區每月750免費時數，頻繁觸發可能使其接近整月運行；正式啟用前核對同工作區用量與費用限制，不升級或自動啟用付費方案。

## 匿名裝置識別與最少保存

新增獨立匿名裝置識別，不沿用Google User ID，也不把裝置待辦匯入登入帳號。以高熵隨機裝置憑證配合HttpOnly、Secure、SameSite嚴格、限API路徑的cookie；DB只存其雜湊。公開GET清單仍不解析私人登入／裝置資料。

僅在使用者開啟提醒後保存：加密的PushSubscription端點與公鑰／auth資料、裝置版本／有效期、公開公告ID／來源類型、本機待辦不可猜的識別、提醒日期時間、到期界線、確認標記、來源版本與狀態revision。通知標題與來源連結由公開表取得，不接受或保存整份card、私人修正文字、Gmail資料、Email、電話或任意跳轉網址。訂閱端點本身是敏感能力網址，不進日誌、公開JSON、分析工具或錯誤正文。

舊待辦若沒有公開公告ID，只以既有source_ref中的可靠來源key與官方canonical URL精確查公開表，不發網路查找、不以標題合併；找不到時提示重新核對來源，保留舊待辦。

前端加入、完成、稍後、移除原流程仍先完成IndexedDB交易；獨立reminder模組才同步使用者已啟用的提醒。用持久outbox與版本處理斷線／分頁競爭；未開啟提醒、合成示範及私人Gmail待辦不得被這個模組上傳。清除瀏覽器資料可能失去本機管理能力，提供先關閉提醒的說明；伺服器到期清理及410失效處理限制殘留，不承諾瀏覽器清除會立即通知伺服器。

## API、權限與防濫用

新增/api/push下的公開設定、裝置訂閱／停用、提醒查詢／變更及測試通知介面；內部POST /internal/push/run只接受獨立觸發Secret、固定空body。前端寫入需同源Origin、非簡單JSON請求、匿名裝置憑證及revision驗證，不開跨來源CORS。不存在裝置／其他裝置識別一律不可讀寫，不暴露他人是否訂閱。

裝置建立、測試發送、訂閱更新及提醒建立需持久限流與每裝置／全站上限；限制body、字串、日期範圍、金鑰長度，拒絕未知欄位。不能信任任意X-Forwarded-For；正式環境先核對受信代理設定。速率桶不保存原始IP，採短期具祕密雜湊。上限與超限提示列入計畫及測試，避免匿名介面變成開放推播中繼。

只接受經核實的Apple／Google／Mozilla推播服務端點；精確允許主機、HTTPS與公網DNS／連線位址，拒絕userinfo、內網位址、轉址與任意目的地。使用標準Web Push函式庫處理VAPID及加密，保持TLS驗證；不得自行降低安全限制以求送達。正式計畫要核對實際函式庫API、允許端點及依賴版本，不臆造可用介面。

## 持久排程與發送語義

0011加上私有push_devices、push_reminders及必要的排程租約／短期限流資料。既有公開同步角色不取得新表權限。重啟、部署、裝置分頁競爭與同時觸發不能重複建立同一提醒。

每輪有界處理：依到期時間領取工作，短交易claim與revision／裝置版本fence，網路在交易外；發送前再次核對未取消、未過期與版本。總時間預算與批次上限明列，未完保留pending並顯示延遲，不假報已通知。成功只表示推播服務接受，不代表裝置已顯示或使用者已讀。傳輸逾時結果不明須記為unknown，不盲目重送；可確定的429／5xx有界退避。404／410停用失效訂閱，清除端點，相關工作停止。

通知payload只含同源公開詳情路徑、公開標題、通知ID與有效期；Service Worker顯示可見通知，點擊回正確公告。使用固定tag減少重複，不能用silent push當背景計時器。過期工作不再送，TTL不得超出已確認的有效提醒窗。測試通知為明確可見測試，不冒充公告截止提醒。

## Cloudflare觸發器與設定

Worker僅有scheduled處理，約每5分鐘向固定Render內部路徑POST，禁止轉址與任意URL輸入、設定有界逾時；fetch對外入口預設404。只存獨立觸發Secret，不存Neon管理連線、Gmail、OAuth、Session或VAPID私鑰。日誌只輸出安全計數／錯誤碼。重複／忙碌安全結束，真正失敗留可查紀錄。

Render新增預設關閉的PushSettings、獨立VAPID金鑰／subject及觸發Secret；公開設定只回VAPID公鑰與功能狀態。無有效設定不能啟用。新的祕密值不得出聊天、檔案版本或日誌；若透過瀏覽器設定，憑證輸入與儲存由使用者本人完成。Cloudflare帳號、免費方案與實際部署權限在正式啟用前核對。

## iPhone與加入主畫面引導（推播核心完成後）

支援iOS16.4以上的主畫面網頁App；先偵測能力及standalone狀態，再由使用者點擊開啟通知，不能初次載入便要求權限。iPhone普通分頁顯示需由主畫面App開啟的狀態，不宣稱已訂閱。準備公開VAPID公鑰與Service Worker就緒狀態後才允許點擊；點擊處理直接呼叫訂閱／權限API，不能先等待後端網路而失去使用者手勢。訂閱成功後才登記伺服器；後端保存失敗顯示「尚未完成啟用」，不得因瀏覽器已授權就顯示提醒已建立。

第二段新增免登入可見「加入主畫面」入口與繁中步驟。iPhone提供Safari分享→加入主畫面→新增→從圖示開啟的指引；其他支援安裝提示的瀏覽器由使用者點擊後呼叫，不支援時提供選單步驟。已安裝時顯示已在App模式，不重複打擾；關閉引導不影響瀏覽。既有manifest、圖示、service worker沿用，只改必要通知與引導部分，不重做配色。

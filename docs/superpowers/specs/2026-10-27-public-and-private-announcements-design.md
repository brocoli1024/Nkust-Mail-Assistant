# 公開校園公告與私人 Gmail 整合設計

狀態：使用者於 2026-10-27 明確回覆「設計通過」；實作計畫另待審閱，尚未實作或部署。

## 1. 已確認的目標

- 使用者希望免費分享網址，讓一般訪客免登入閱讀校園公告。
- 同一網站保留原有登入後的私人 Gmail 公告功能。
- 第一個公開來源為 https://www.nkust.edu.tw/p/422-1000-1001.php 。
- 全部收錄，再提供學生相關篩選；不因分類或學生相關判斷而拒絕收錄。
- 不公開現有私人郵件、資料庫內容、Gmail 授權或帳號資訊。

## 2. 來源證據與限制

本次瀏覽器實查確認「最新消息」頁免登入可讀，包含日期、標題、原文連結、分頁及 RSS 連結。
當時清單顯示 193 頁；這只是觀察值，不能寫死。原文分散在各處室及公務郵件網站。

官方 RSS：https://www.nkust.edu.tw/p/503-1000-1001.php 。瀏覽器可讀取近期公告及部分內文；
本次尚未驗證 XML 解析合約、穩定條目識別碼、完整清單涵蓋率及翻頁請求格式。
搜尋索引曾回傳較舊內容，直接 HTTP 抓取也曾逾時，因此不得用搜尋快取作為正式同步來源。

「全部收錄」指指定公開清單中可取得的公告，不代表全校各網站的所有公告，也不保證涵蓋所有 Gmail 通知。
RSS 不是完整歷史庫。正式標示歷史收錄完成前，必須驗證清單分頁、可達頁面及中斷續跑能力。
學校公開來源的自動讀取條件仍需核對；未確認前不批次抓取歷史全文。

## 3. 方案比較與建議

| 方案 | 優點 | 限制 |
| --- | --- | --- |
| 僅使用 RSS | 範圍小，適合先驗證近期資料 | 無法宣稱歷史全部收錄 |
| RSS 增量＋清單補歷史（建議） | 可逐步補齊指定來源並持續更新 | 需驗證分頁、去重與續跑 |
| 逐一爬取全校各處室 | 可擴大來源 | 版型與維護成本高，不列入第一版 |

採第二方案，分階段驗收：先交付近期公開公告，再交付可續跑的歷史補收。
介面顯示收錄起點、最後成功更新及補收狀態，不把第一批 RSS 資料稱為全部歷史。

## 4. 使用流程

- `/`：回傳公開介紹與公開公告入口，不直接導向 Google 授權。
- `/public/announcements`：免登入清單；預設全部，提供學生相關、分類、關鍵字與分頁。
- `/public/announcements/{id}`：只展示公開來源取得的資料，附發布日期、原文與更新資訊。
- `/announcements`：維持目前依帳號隔離的私人郵件公告；登入後導覽同時提供公開公告與我的郵件。
- 不在第一版把兩種來源混成同一清單，也不新增只有 Google 基本登入而未授權 Gmail 的帳號流程。

學生相關篩選是方便瀏覽的提示，不是資格判定。預設關閉，不影響資料保存。
規則只根據已取得的公開標題及公開內容判斷，保存規則版本與命中原因；無法判定者標記未知。
篩選區提示可能漏判，提供清除篩選回到全部。徵才、教師研習等不能只因含「課程」就確定為學生相關。

## 5. 資料與整合邊界

在現有多人資料庫新增獨立公開資料表，以新增 migration 處理，不放寬私人 Announcement 的 user_id 約束。

公開公告至少保存：內部 ID、來源、來源識別碼（若可驗證）、原文 URL、標題、發布日期、
來源提供的摘要、分類及版本、學生相關狀態及原因、首次發現／最近確認／最近變更時間。
無法驗證的活動日期或截止日保留未知；不能用發布日期代替。

來源識別碼或保守正規化後的 URL 作為唯一性依據。同一 URL 更新既有紀錄；不同 URL 不因標題相同而合併。
正規化不得任意移除來源需要的查詢參數。先驗證 RSS link / guid 與清單原文 URL 的關係。
未再出現在有限 RSS 中不表示原文刪除，不據此刪除本機資料。

同步紀錄另存執行狀態、開始／完成時間、新增／更新／失敗數及補收游標；不保存秘密或任意外部錯誤原文。
只有資料交易提交後才推進游標；來源失敗保留最後成功資料。
帳號刪除只刪本人私人資料，不刪公開資料。公開路由不 join 或回退讀取私人表。

## 6. 收集與免費營運

第一版以維護者 CLI 執行同步及歷史補收，不提供匿名訪客觸發爬取的 HTTP 入口。
每次同步有請求數、大小、時間與頁數上限，歷史補收可分批續跑；不在一次網頁請求中掃描全部歷史。
使用固定設定的來源與嚴格網址驗證、有限轉址和安全 XML 解析；不接受訪客提交任意抓取網址。
RSS 文字與 HTML 均視為不可信輸入，以跳脫後文字呈現；不直接插入來源腳本或 HTML。

第一版只讀清單與 RSS，原文以連結提供。自動抓取不同處室全文、附件及 AI 摘要不列入第一版。
尚未驗證免費排程執行環境，不承諾固定時間自動更新；不能依賴會休眠的 web 程序提供可靠排程。
初期由維護者執行 CLI，網站顯示真實最後成功更新時間；後續另選排程方式。

## 7. 現有程式需配合的項目

- 現有 `app.web` 與 `app.deployment_check` 寫死 migration revision 0005，新增公開表後需同步更新驗證。
- 新增公開來源 adapter、公開資料存取服務及維護指令；分類盡量重用現有純規則函式。
- 公開模板可沿用多人版視覺元件，但公開導覽不能依賴使用者 session。
- 公開閱讀路由不應因沒有 cookie 而查詢私人 session；整個服務目前仍在啟動時要求 OAuth 設定，第一版保留此整合部署前提。
- 既有單人版 `app.main`、私人同步與 Google scope 不因公開版而擴大。
- 工作目錄已有單人 Dashboard 樣式、腳本、模板及開放檢查文件的未提交修改；實作前確認歸屬並保留。

## 8. 驗收與交付順序

1. 驗證 RSS 格式及與清單條目的對應，保存最少必要且去識別化的測試樣本；核對自動讀取條件。
2. 新增公開表、RSS 同步及免登入清單，驗證新增、更新、重跑不重複、搜尋、學生篩選與來源失敗保留資料。
3. 驗證公開清單與詳情永不回傳私人郵件；私人公告仍需登入且無法跨帳號，來源惡意 HTML 不執行。
4. 驗證分頁補收、重試與中斷續跑後才補歷史；來源不允許或技術不可行時，保留近期版並明示缺口。
5. 使用獨立合成 SQLite 及指定測試 PostgreSQL 檢查 migration 和查詢；部署前完成正式資料備份與必要驗收。

完成標準：陌生訪客開網址即可閱讀指定來源已收錄公告；學生篩選可清除；私人資料維持隔離；
更新失敗及歷史缺口可見；無匿名寫入或抓取入口；不宣稱 Gmail 對所有帳號開放。

# 第三階段：我的待辦設計（2026-10-29）

狀態：銜接設計；尚未實作，不代表正式環境已有功能。沿用本對話授權與既有 FastAPI／SQLAlchemy／原生 IndexedDB，不新增服務。

## 目標與操作

學生在行動卡核對日期與依據後，明確按「加入我的待辦」。系統辨識可採取行動只是提示，不建立待辦、不推定資格。首次加入保存使用者當時看到的摘要、來源連結、來源身份與 baseline_hash，並提示來源後續可能更新。截止待確認仍可加入，但不排入確定截止清單。

狀態只有進行中、已完成、稍後處理。完成可重新開啟；移除僅移除自己的待辦，不刪公告或修正。稍後處理提供「明天上午 09:00（台灣時間）」並在按下前顯示確切年月日時間，不宣稱會發送通知。到時重新開啟或重新整理待辦頁，項目自動出現在進行中；開著頁面時以每分鐘重算可見性。截止早於稍後時間時明顯提示，避免延後錯過期限。

首頁先顯示裝置待辦、已知日期的即將截止（七日內，含今天）；無截止排後，逾期獨立標示。完整頁提供進行中／稍後／已完成篩選、來源原文連結及空白／讀取／錯誤狀態。不把載入失敗當沒有待辦。登入使用者私人待辦另由帳號頁顯示；匿名公開首頁不解析 cookie 或查私人表。

## 保存取捨

選擇沿用第二階段兩種保存界線：公開公告待辦保存在此瀏覽器 IndexedDB，免登入、不上傳、不跨裝置；共用瀏覽器可能看見，清除資料會遺失。私人 Gmail 待辦只保存至登入帳號的資料庫，所有讀寫再次核對 Google subject 與 owner，從不存私人原文到 IndexedDB。登入／登出不自動匯入或合併裝置與帳號待辦，介面明確分區；將來跨裝置整合須另行明示。

demo 待辦只在同頁記憶體，重載即重設，不污染真實待辦。

## 實際修改範圍

1. 新增 todo schema／純狀態與台灣時間運算、私人 todo 模型及 additive migration 0008。待辦依 Email 及來源索引／指紋保留身份，不以可重用的 Announcement ID 作唯一來源；刪帳號 CASCADE。
2. 新增 owner-scoped todo service／HTML 路由，沿用身分、CSRF、同來源表單及 expected_revision 比較；同帳號寫入先鎖 User，狀態更新 CAS，失敗不假成功。
3. 擴充 IndexedDB 至 v2，新增獨立 publicTodos store；保留 v1 修正紀錄。只接 public source，單筆交易 CAS，等待 transaction complete；blocked／quota／損壞均保留舊資料並提供重試。
4. 共用待辦操作模板、公開／私人／demo 詳情接線，首頁裝置待辦區、私人總覽帳號待辦區、繁中手機可操作待辦頁。公開與私人載入程式分開。
5. 測試涵蓋明確加入、去重僅同一可靠來源、保存／重載、完成／重開／移除、台灣跨日及稍後重新出現、截止提醒、雙分頁 CAS、跨帳號／Google 身分／刪除、重解析、v1→v2 無資料遺失及錯誤提示。瀏覽器用合成資料驗收，完整回歸後再稱完成。

## 第四、第五階段銜接

待辦保存截止日期及來源，但不把未確認日期升級。未來 .ics 需使用者選活動或截止並確認日期；明確無時間採全天，Asia/Taipei；只宣稱已下載檔案，不宣稱已加入行事曆。

跨來源合併只接受官方 URL／可靠識別碼，不以相似標題自動合併。保留原來源與更新歷史，來源變更需顯示提醒；私人郵件內容不可出現在公開公告、裝置待辦或其他帳號。第三階段不實作自動合併或行事曆授權。

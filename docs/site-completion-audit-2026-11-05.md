## 優先處理的五組缺口

| 優先 | 證據與實際缺口 | 預期完成條件 |
|---|---|---|
| P0 來源持續性 | office-refresh只讀既有公開表；管理者未加入新URL就永遠只有既有資料。來源時間只代表重讀，無新信檢查時間。 | 指定帳號發現→公開檢查→持久候選→發布→可重試；顯示兩種更新狀態與實際覆蓋。 |
| P1 來源與入口語義 | 「公開公告／公務公告／全部公務公告」容易被理解為同一資料範圍；公開頁文案「全部收錄」過度廣泛。 | 清楚標示「學校最新消息」「已收錄公務通知」與各筆數／涵蓋日期；全部表示本站收錄且搜尋仍有效。兩區相互導引，搜尋無結果可轉另一來源。 |
| P1 郵件閱讀與待辦銜接 | 私人announcement_detail.html仍include action_card.html及3句擷取摘要，與使用者不需郵件行動卡的要求有落差；公務詳情沒有加入待辦入口。 | 公務／私人通知先看內容重點，保留班別、福利、限制；需要時以簡潔操作列自行加入待辦。沒有確定日期就不造期限。保留既有私人待辦與ICS能力，不能只刪卡片導致功能消失。 |
| P2 操作完整性 | 校區已原地套用，但搜尋／分類、全部入口仍有整頁導覽；條件摘要、清除篩選、共用裝置提示需一致。 | 按實際學生任務統一搜尋、排序、清除、返回、載入與失敗重試；保持URL、分頁與手機閱讀位置一致，不重寫成新SPA。 |
| P2 營運與說明 | privacy頁仍只描述RSS公開來源，未涵蓋公務來源與管理者發現管線；原OAuth Testing、未完成全面開放／持續備份驗收。 | 更新資料流／保存／來源說明、管理者停用及重新授權狀態；完成可回復部署與實際排程證據。OAuth上線或付費事項另確認，不假稱全面完成。 |

## 分段交付

先實作來源管線及明確收錄狀態，第二段修入口與內容閱讀／待辦銜接，第三段統一互動與整站驗收。每段有實際驗收及限制，不再把規劃、合成資料或功能存在視為整站完成。

暫不增加聊天、推薦、額外配色、全面擴充其他校方寄件者或推播。一般學生仍免登入；私人Gmail整合保持選用。來源管線詳細設計見superpowers/specs/2026-11-05-office-discovery-design.md。
